# 16 混合精度扩展（HOV / MXP）

主要来源：Albert Ou 硕士论文《Mixed Precision Vector Processors》（EECS-2015-265）、博士论文 8.7 节、评估报告。评估报告称带混合精度的设计为 **HOV**（high-occupancy vector lanes），博士论文称 **MXP**，开源代码参数为 `HwachaConfPrec`。

## 1. 动机

- 固定功能加速器靠最小化字宽获得能效；通用处理器的数据通路却固定在最大精度。
- 同一内核内很少有单一精度最优：地址 64 位、数据 32 位、传感器输入 16 位；FMA 的 n 位乘积累加到 2n 位累加器。
- 向量架构天然适合子字并行：元素之间无依赖，宽数据通路可以直接切成多个窄元素。
- 收益：寄存器堆访问和操作数互联利用率提高；额外的窄 FMA 面积小；吞吐提高后可以更快 race-to-halt；元素存储更密集，**同样的寄存器堆容量支持更长向量**，更长的向量又加深了解耦缓冲。

## 2. 编程模型

**配置**：`vsetcfg #v64, #pred, #v32, #v16` 分别声明 64/32/16 位向量寄存器的数量。HVL 计算按 `4·nvvd + 2·nvvw + nvvh` 加权（一个 128 位行放 2 个 d、4 个 w、8 个 h）。论文图 6.3 的例子：10 行寄存器堆，2 个 64 位寄存器得 HVL 5，改为 1 个 64 位 + 1 个 32 位得 HVL 6。

**寄存器编号**：架构上仍是 vv0–vv255 的统一编号空间，但按配置分成三段：前 nvvd 个是 64 位寄存器，接着 nvvw 个是 32 位，最后 nvvh 个是 16 位。指令引用的寄存器精度必须不低于指令要求的精度，否则非法指令异常（例如对配置为 16 位的寄存器执行 `.s` 运算）。

**指令**：每条浮点指令固定精度（`.d/.s/.h`），另有加宽指令（`vfmadd.d.h`、`vfadd.s.h`、`vfmul.d.s` 等）和转换指令。整数指令按 64/32 位（`*w`）区分。评估用的 `hs*`/`sd*` 内核就是"输入输出窄精度、中间计算宽精度"的写法。

与 packed-SIMD 的关键区别：所有精度下每个向量寄存器的**元素数相同**（都是 vlen），因此不同精度的操作可以直接 chaining，不需要拆分寄存器。

## 3. 微架构改动

### 3.1 寄存器映射

- 所有相同索引的元素必须落在同一 SRAM bank，以保持 µop 调度对每个 bank 一致。
- SRAM 被分为 doubleword、word、halfword 三个区域，架构寄存器的物理起始地址 = 区域基址 + 寄存器号，元素按该类型寄存器总数为步长遍历。SRAM 大小不变。
- 谓词寄存器堆加宽到 8 位，让一行 SRAM 中最多 8 个 halfword 元素的谓词能一次读出；谓词映射同样条带化。

### 3.2 空间并行

- 一个操作的速率由源/目的寄存器精度和该操作可用的并行功能单元数共同决定，二者在译码时确定并记入主序列器条目。
- SRAM 端口与操作数锁存器之间插入一组 mux，根据速率和 µop 中的子字索引解包并**符号扩展**子字（符号扩展是为了让有无混合精度的实现结果一致）；写口前有反向的重打包 mux。
- 每个 lane 额外例化 2 个单精度 FMA 和 6 个半精度 FMA，以及额外的半↔单转换单元，使窄精度操作达到满吞吐：每 lane 每周期 2 个 DP、4 个 SP 或 8 个 HP FMA（每簇）。

### 3.3 多速率 chaining

- chaining 允许后续操作消费前一操作的中间结果。速率不同后，更新更快的操作可能**追上**更慢的旧操作。
- 仅比较序列器条目的剩余 vlen 不够，因为 vlen 在发射时而非提交时更新，strip 可能仍在飞。
- 保守做法（相关操作间保持大于一个 strip 的距离）会抵消 chaining 收益。实际做法是序列器检查展开器移位寄存器中待处理的写 µop，把原来的"物理地址相等"检查扩展为**区间重叠**检查。主要代价是比较器数量增加。

## 4. 评估结果（单 lane，28nm）

| | 基线 | HOV |
|---|---|---|
| 面积（PNR） | 2.11 mm² | 2.21 mm² |
| 频率（PNR） | 1.11 GHz | 1.06 GHz |
| 面积开销 | – | 1 lane 4.0%，4 lane 12.5% |

开销来源：额外功能单元占大头；bank 因谓词寄存器堆加宽略增；控制逻辑因展开器冒险检查的比较器增加。

性能与能耗趋势：
- `*axpy`：访存受限，HOV 几乎无收益，能耗略高（额外功能单元的动态能耗，可能是时钟门控不够充分）。
- `dgemm`/`sdgemm`：DP FMA 数量相同，无差别。
- `sgemm`：适度加速，未达理论 2 倍。
- `hgemm`/`hsgemm`：最显著加速，但次线性（吞吐翻两番后访存延迟按 Amdahl 定律凸显）。手工优化的 `hsgemm-unroll-opt` 相对基线 OpenCL 版本达到 12.0 倍（基线）和 19.0 倍（HOV）。
- 能耗随精度降低呈一致下降趋势；`hsfilter` 上 HOV 优于基线。

## 5. 使用注意

- `HwachaConfPrec` 默认 false；打开后 `vsetcfg` 需要多个周期（RoCC 单元有 `cfg_busy` 状态机），期间 `cfg.valid` 为假。
- 序列器和展开器中与 `confprec` 相关的路径（`update_pack`、`RateLogic`、`PackLogic`）只在启用时综合。
- 论文建议的未来方向是多态指令集（精度由寄存器配置决定），可以省下大量操作码，但会失去"寄存器里放比配置更窄的值"的能力。
