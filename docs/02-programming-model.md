# 02 编程方法学

## 1. 两个线程

Hwacha 汇编编程模型把一个数据并行内核拆成两部分：

| 线程 | 运行位置 | 指令长度 | 职责 |
|---|---|---|---|
| 控制线程（control thread） | Rocket 标量核 | 32 位，RoCC 格式，custom-0/1 主操作码 | 配置向量单元、stripmine 循环、传递标量与地址、发起向量取指、与 OS 交互 |
| 工作线程（worker thread） | Hwacha 向量单元 | 64 位，RISC-V 变长编码（低 7 位 `0111111`） | 真正的向量、向量-标量、标量计算与访存 |

控制线程通过 `vf` 指令指向工作线程的第一条指令，工作线程执行到 `vstop` 为止。工作线程的这段代码就叫**向量取指块**。

## 2. 用户可见寄存器状态

| 寄存器 | 数量 | 宽度 | 控制线程 | 工作线程 |
|---|---|---|---|---|
| 向量数据寄存器 vv0–vv255 | 最多 256（由 vsetcfg 决定） | 每元素 8/16/32/64 位整数或 h/s/d 浮点，长度 vlen | 不可直接访问 | 读写 |
| 向量谓词寄存器 vp0–vp15 | 最多 16 | 每元素 1 位 | 不可访问 | 读写 |
| 向量共享寄存器 vs0–vs63 | 64（vs0 恒 0） | 64 位标量 | `vmcs` 写 | 读写 |
| 向量地址寄存器 va0–va31 | 32 | 64 位指针/步长 | `vmca` 写 | **只读** |
| vcfg | 1 | 64 位 | `vsetcfg`/`vgetcfg` | 隐式 |
| vlen | 1 | 64 位 | `vsetvl`/`vgetvl` | 隐式 |

vs 与 va 的区别是刻意的：va 在工作线程中只读，这是 VRU 非投机预取的基础。需要在块内计算出来的地址（例如 gather 的基址）只能放在 vs 里，而以 vs 为基址的访存 VRU 不会预取。

## 3. 标准代码骨架

以 CSAXPY 为例（a0=n，a1=cond，a2=a，a3=x，a4=y）：

```asm
csaxpy_control_thread:
    vsetcfg #v64, #v32, #v16, #vp   # 声明寄存器用量，硬件据此确定最大 HVL
    vmcs    vs1, a2                 # 标量 a 送入共享寄存器
stripmine_loop:
    vsetvl  t0, a0                  # vlen = min(a0, HVL)，返回给 t0
    vmca    va0, a1                 # cond 指针
    vmca    va1, a3                 # x 指针
    vmca    va2, a4                 # y 指针
    vf      csaxpy_worker_thread    # 发起向量取指块
    add     a1, a1, t0              # 地址簿记，按整段向量一次完成
    slli    t1, t0, 2
    add     a3, a3, t1
    add     a4, a4, t1
    sub     a0, a0, t0
    bnez    a0, stripmine_loop
    ret

csaxpy_worker_thread:
         vlb     vv0, (va0)          # 加载条件数组
         vcmpez  vp0, vv0            # vp0 = (vv0 == 0)
    !vp0 vlw     vv0, (va1)          # 条件为真的元素才加载 x
    !vp0 vlw     vv1, (va2)
    !vp0 vfma    vv0, vv0, vs1, vv1  # 向量 × 共享标量 + 向量
    !vp0 vsw     vv0, (va2)
         vstop
```

要点：

1. **`vsetcfg` 只做一次**，放在内核入口。它会把 vlen 清零，所以之后必须 `vsetvl`。
2. **`vsetvl` 每次迭代都做**，返回值就是本次实际处理的元素数，用它更新指针和剩余计数，不需要尾部代码。
3. **`vmca` 在 `vf` 之前**，把本轮的基址交给硬件。`vmcs` 传递的是跨迭代不变的标量，放在循环外。
4. 工作线程里的 `@[!]p` 前缀表示按 vp 掩码执行，`!` 表示取反；`@all` 表示不带谓词；`@s` 表示纯标量指令（所有操作数都是 vs）。
5. 同一份代码在更宽的机器上自动获得更长的 HVL，无需重新编译。

## 4. 控制线程与工作线程之间的同步

- `vf` 是**异步**的：控制线程发出后立即返回继续执行，Hwacha 在后台执行向量块。控制线程可以连续发多个 `vf`，它们排在向量命令队列（VCMDQ）中顺序执行。
- 控制线程读取向量单元写入内存的结果前需要 `fence`：Hwacha 扩展了 RISC-V fence 语义，用于对控制线程与工作线程之间的访存排序（微架构上由内存排序单元 MOU 实现，见 `modules/15-memory-ordering-exceptions.md`）。
- 工作线程内部用 `vfence` 对块内前后访存排序。
- 归约结果（`vfirst`、一致性分支的判定）先在各 lane 计算，再在标量单元汇总；标量单元靠 scoreboard 等待。
- 浮点动态舍入模式在 `vf` 发出时从控制线程的 `frm` 继承；工作线程产生的浮点异常标志累积到控制线程的 `fflags`。工作线程本身不能读写 `frm`/`fflags`。

## 5. 编译器如何把 OpenCL 映射到 Hwacha

Berkeley 基于 PoCL 运行时和自定义 LLVM 后端实现了一个**标量化 OpenCL 编译器**。核心变换：

1. **方差分析（variance analysis）**：识别对所有 work-item 一致的值（thread-invariant），在 LLVM IR 和机器指令两个层次上进行。
2. **标量化**：一致的值放进 vs 寄存器，一致的计算变成 `@s` 标量指令，避免在向量寄存器里重复存放。
3. **访存模式提升**：由 `get_global_id(0)` 线性推导的地址提升为单位步长或常量步长访存，基址放进 va。这一步对解耦架构至关重要，因为只有 va 基址的访存才能被 VRU 预取。
4. **谓词化**：if-then-else 与循环用谓词寄存器和一致性分支实现，不依赖硬件分歧管理。
5. **stripmine 生成**：把 SPMD kernel 的一维 launch 变成控制线程的 stripmine 循环，每次 `vf` 处理 vlen 个 work-item。

评估中 OpenCL 编译版本与手写汇编之间有明显差距，主要原因是手写代码会**跨向量取指块保留数据在 VRF 中**（例如 gemm-opt 把 C 的向量常驻寄存器堆），而 OpenCL 的编程模型天然让每个 kernel 调用在开头加载、结尾存回。

## 6. 性能编程要点

**让访存可预取**
- 尽量用 va 基址的单位步长 / 常量步长 `vl*`/`vls*`/`vlseg*`，而不是以 vs 为基址的 indexed 访存。
- 避免在块内计算出基址后再访存；把能提前算好的地址放到控制线程用 `vmca` 传入。

**让寄存器堆物尽其用**
- `vsetcfg` 精确声明寄存器用量，多余的声明会缩短 HVL。
- 使用窄精度声明（#v32、#v16）并配合 `.s`/`.h` 指令可以获得更长向量和更高吞吐（需硬件启用混合精度）。
- 跨向量块保留累加器（如 gemm 的 C 块）在 VRF 中，减少每块的加载/存储。

**让功能单元饱和**
- 一个 lane 的 128 位数据通路每周期供给 2 个 64 位、4 个 32 位或 8 个 16 位元素；两个 FMA 簇（VFU0、VFU1）可并行。
- 相邻的向量指令若无冒险会自动 chaining，无需手工调度。
- 变延迟操作（除法、开方、整数除）走独立的解耦路径，穿插在其他操作之间即可隐藏延迟。

**谓词的成本**
- 谓词只影响写回与访存，不减少计算周期（VMU 只对 2 的幂长度的假谓词串做有限的 density-time skipping）。
- 分支大多数元素都会走同一方向时，用 `vcjal.all`/`.any` 跳过整段代码收益最大。

**多 lane**
- 元素按 lane stride（默认 1 个 strip = 8 个 64 位元素）交错分配到各 lane。单位步长基址若不对齐到 128 位，相邻 lane 会重复请求同一 cache line，浪费少量带宽。

## 7. 与传统向量机代码的差异速查

| 传统向量机 | Hwacha |
|---|---|
| 向量指令与标量指令混排在同一流 | 向量指令必须在向量取指块中 |
| 标量操作数直接引用标量核寄存器 | 先 `vmcs` 到 vs，或在块内用 `@s` 指令计算 |
| 访存基址直接用标量寄存器 | 先 `vmca` 到 va（可预取）或放 vs（不可预取） |
| 每次 stripmine 重新取指全部向量指令 | 控制线程只发一条 `vf` |
| 一般只有一个掩码寄存器 | 16 个谓词寄存器，任意指令可取反谓词 |
